# Unit 2 NFR Design Patterns

1. Fail-fast capability gate before generic optimisation.
2. Strict value object for positive budget limits.
3. Named-over-options-over-default precedence at the public boundary.
4. Warm-start-first retained-baseline pattern.
5. Request-local memoization by exact coordinate tuple.
6. Closed candidate-local versus fatal failure boundary.
7. Bounded diagnostic reservoir with complete numeric counts.
8. Engine-neutral generic optimiser adapter.
9. Single/multiperiod parity through shared contracts.
10. Deterministic call-count tests plus separately documented real-engine profile.

Infrastructure, distributed scaling, retry services, authentication, and
compliance controls are not applicable because this is an in-process numerical
library change with disabled Security and Resiliency extensions.
