# HEN Execution

## Overview
Resolves synthesis settings, and the options the search width and depth set, from a prepared problem, and executes batches of synthesis tasks, either with the local solver executor or a deterministic fake. The `targeting` package builds tasks and calls the executors here; `results` and `reporting` consume the outcomes. Solver models come from `../models` and solver arrays from `../solver`.

## Interface
- `SynthesisWorkflowSettings` (`settings.py`): frozen dataclass of resolved HENS controls, with derived properties (`runs_evolution`, `runs_thermal_derivative_method`, `milp_networks_seed_evolution`, EVM branch breadth), `heuristic_pdm_networks` (the heuristic network cap per multiplier, 0 for none), `heuristic_pdm_evolution_seeds` (heuristic networks per multiplier that seed evolution, cheapest first), `runs_milp_pinch_design` (the MILP at every multiplier: `pdm_milp`, or no heuristic networks) and `solver_for` / `solver_options_for` per method; for the heuristic pinch design method `solver_for` gives HiGHS when it is installed (`heuristic_solver`), otherwise the PDM solver, and `solver_options_for` gives the PDM options only when that is the PDM solver [settings.py:heuristic_solver] [executor.py:_solver_for_task].
- `workflow_settings_from_problem` (`settings.py`): reads `master_zone.config.hens` into settings; `dt_cont_multipliers` is `HENS_DT_CONT_MULTIPLIERS`, or the search width's multipliers when it is unset, and the depth-set options resolve the same way [search.py:resolve_search].
- `StagePackingScope` (`settings.py`): alias for the stage-packing scope string.
- `configured_stage_solver(hens, option)` and `stage_solver_options(hens, stage, solver)` (`settings.py`): a stage's solver, with SCIP in place of a default (`HENS_SOLVER_PDM`, `_TDM` or `_EVM`) that is not installed, and its options, which are empty when the solver fell back. Workflow settings, the executor's task solvers and fixed-structure duty optimisation all resolve through them [settings.py:configured_stage_solver, stage_solver_options] [executor.py:_solver_for_task] [duty_optimisation.py:FixedStructureDutyExecutor._solve].
- `WIDTH_MULTIPLIERS`, `DEPTH_LEVELS`, `DepthLevel`, `ResolvedSearch`, `resolve_search`, `reference_dt_cont_multiplier`, `scaled_heuristic_networks`, `FULL_HEURISTIC_STREAMS`, `MIN_SCALED_HEURISTIC_NETWORKS`, `SCALED_HEURISTIC_DEPTHS` (`search.py`): the search levels, the options they set after explicit overrides, and the multiplier a run falls back to. Given the case's process stream count (`workflow_settings_from_problem` passes the master zone's hot and cold streams), `resolve_search` scales the heuristic network count of depths 0 and 1 when `HENS_HEURISTIC_PDM_NETWORKS` is unset: up to 30 streams the level's count, above it the count times (30 / streams) squared, at least 10.
- `SynthesisExecutor` (`executor.py`): protocol with `execute(tasks, *, problem, parent_outcomes, max_parallel)`.
- `LocalSynthesisExecutor` (`executor.py`): builds an internal model per task, solves it (optionally in a process pool), extracts the network and returns outcomes. `handoff_queue_factory` (default: a `multiprocessing.Manager` queue) makes the queue pool workers send admitted networks back on. `session()` is a context manager that keeps one worker pool for every `execute` call made inside it.
- `FakeSynthesisExecutor` (`fake_executor.py`): deterministic no-solver executor for workflow tests.
- `has_recovery_topology`, `is_utility_only_outcome`, `is_pdm_variant_outcome`, `required_topology_restrictions_from_outcome`, `topology_restrictions_from_network`, `stage_count_from_network`, `dt_cont_multiplier_from_network`, `derivative_threshold_from_network` (`task_builders.py`): helpers that derive downstream task inputs from outcomes or seed networks.
- Couenne fallback predicates (`fallbacks.py`): private (underscore) helpers used by `targeting/open_hens_method.py`.

## Invariants
- A downstream task needs a successful parent outcome and the parent's in-process solver problem; `_parent_problem` raises `WorkflowContractError`, but `LocalSynthesisExecutor.execute` catches it and returns a failed task outcome carrying the message, while `FakeSynthesisExecutor` lets it propagate [executor.py:LocalSynthesisExecutor._parent_problem] [executor.py:LocalSynthesisExecutor.execute] [fake_executor.py:FakeSynthesisExecutor.execute].
- Within one serial `execute` call (one worker, or a worker pool that could not start), every task gets the same new store of solved evolution topologies, so evolution tasks of that stage reuse each other's solved candidates; tasks solved in pool workers get none, so their results do not depend on which tasks shared a worker [executor.py:LocalSynthesisExecutor.execute, _start_pool] [executor.py:_solve_built_task].
- Tasks are built inside pool workers only when no parent outcomes exist, no task has a parent and more than one worker is in use [executor.py:_can_build_tasks_in_workers].
- Outside a session each `execute` call starts a pool of `min(max_parallel, tasks)` workers and closes it when its tasks are done. Inside `session()` the first stage that needs a pool starts one of `max_parallel` workers, every later stage reuses it, and the session closes it; a stage left with at most one task to solve does it in process and leaves the session's pool open; a pool a stage fails in (or whose results the caller stops reading) is closed and dropped, so the next stage starts a new one. A pool must be a context manager: its `__enter__` is called when it starts and its `__exit__` when it closes [executor.py:LocalSynthesisExecutor.session, _start_pool, _using, _run].
- A task's internal approach is `2 * THERMAL_DT_CONT * dt_cont_multiplier` (`solver.arrays.nominal_approach_temperature`). PDM models and arrays use it. TDM and ESM models take `max(0.1 K, HENS_MIN_EXCHANGER_APPROACH_SHARE x it)` as their nominal approach, and their arrays are built at `HENS_MIN_EXCHANGER_APPROACH_SHARE x it` (a tiny positive value at a share of 0), so each contribution is scaled by the multiplier times the share (0.25 by default) and each match is held to `max((dtcont_src + dtcont_snk) x m x share, 0.1 K)`, the floor being on the pair (`solver.arrays.pair_minimum_approach`) [executor.py:_task_model_approach_temperature, _task_array_approach_temperature, LocalSynthesisExecutor._build_problem].
- Extracted networks record the task's dt_cont multiplier as `dt_cont_multiplier` in summary metrics and source metadata; a seeded task takes it from there, or the reference multiplier (1.0 when configured, otherwise the first) for a network without one [executor.py:LocalSynthesisExecutor._build_problem] [task_builders.py:dt_cont_multiplier_from_network].
- A solve counts as successful only when `mSuccess == 1` and `verify()` (if present) passes; failures carry a non-empty error string [executor.py:_solve_built_task, _solved_outcome, _failed_task_outcome].
- A PDM task is built with `pdm_network_limits` from `HENS_PDM_MIN_UNIT_NETWORKS` and `HENS_PDM_EXTRA_UNIT_NETWORKS`. Each extra network its problem returns in `pdm_variants` becomes its own task (the PDM task with `pdm_variant: k` added to its settings, so a new task id), outcome and registered problem, right after the PDM task's outcome; the variants are then dropped from the PDM task's problem [executor.py:LocalSynthesisExecutor._pdm_variant_outcomes, _pdm_variant_task].
- A PDM task's stage counts above and below the pinch are the pair in its own `stage_selection` setting (a stage pair candidate), else `HENS_PDM_STAGES`, else each side's own count. `HENS_STAGE_SELECTION` does not set them, and `HENS_PDM_STAGES` does not reach a heuristic pinch design task [executor.py:_pdm_stage_selection].
- A PDM or heuristic pinch design task sets `staged_utilities` when `HENS_UTILITY_PLACEMENT` resolves to "temperature" (`"auto"`, the default, is "price" when the problem's zone tree holds one process zone and "temperature" when it holds more, `_utility_placement`) and its decomposition has more than one hot or more than one cold utility, so its sides hold each utility level at its target with staged heaters and coolers, and passes `HENS_UTILITY_SLICES` as `utility_slicing` [executor.py:_has_utility_levels].
- A task whose settings carry `site_processes` (a site seed's, `../targeting/_stage.py:build_seeded_quality_tasks`) is built with them, with `staged_utilities` and with the site's utility levels (`../site/levels.py:site_utility_system`, each hot utility's `maximum_heat_flow` as its level's import capacity, and `HENS_SITE_LETDOWN_PRICE` in $/MWh as its letdown price, annualised as utility prices are by `COSTING_ANNUAL_OP_TIME`), so its stage-wise model holds each process's levels (as `HENS_SITE_LEVEL_HOLDS` says: `"fixed"` at the targets, `"at_least"` at or above them) and matches streams only within a process [executor.py:LocalSynthesisExecutor._build_problem].
- A heuristic pinch design task builds a PDM problem (pinch decompositions, HiGHS when installed and otherwise the PDM solver, with the PDM options only for the PDM solver, automated stages, no minimum-unit variants) with `heuristic_network_limit` from its `heuristic_networks` setting (50 if absent); its extra networks fan out as above with `heuristic_variant: k`. Heuristic networks are labelled `heuristic_pinch_design_method` [executor.py:LocalSynthesisExecutor._build_problem, _variant_key, _model_framework].
- A successful solve whose solver stopped before converging records `diagnostics["unconverged_termination"]`; it stays a success so downstream tasks can start from it [executor.py:_solve_built_task].
- Stage-packing scope `"auto"` resolves to `"none"` at execution time [executor.py:_stage_packing_scope]. The scope decides packing for PDM and TDM tasks [executor.py:LocalSynthesisExecutor._model_factories_for_task].
- Outcomes are returned in the order of the input tasks [executor.py:LocalSynthesisExecutor._collect_outcomes]. A pool's results are taken as their tasks finish (`submit` and `as_completed`, so a pool needs `submit`), and each task's outcome is offered to the run's records then, not after slower tasks submitted before it; when a solve raises or the stage stops early, the solves still waiting for a worker are cancelled [executor.py:_as_completed, LocalSynthesisExecutor._reported].
- `LocalSynthesisExecutor` sets `admits_outcomes`: it offers each task's outcome to the run's records in this process as that task's result arrives, before the next result is waited for, and each extra pinch design network as it is extracted after the stage's tasks finish [executor.py:LocalSynthesisExecutor._reported, LocalSynthesisExecutor._pdm_variant_outcomes].
- A task whose solve returns no solved model is a failed outcome with the problem's failure reason; when evolution was skipped because its initial model failed (`evolution_skipped`), the outcome records that reason as `diagnostics["evolution_skipped"]` [executor.py:_unsolved_outcome].
- Each candidate an evolution search reports as an improvement is extracted with the task's arrays and labels (`extract_candidate_network`) and offered to the run's records as a success outcome of its task; one that cannot be extracted is logged and dropped. Serially (and in Pyodide) it is admitted in the solving thread. In a pool, the worker puts it on the hand-off queue and a drain thread in this process, running in a copy of the caller's context, admits it; the queue is drained and the thread joined before `execute` returns, and an error the drain hit is raised then [executor.py:_hand_off_candidate, _handed_off, LocalSynthesisExecutor._handoff].
- One `execute` call reads the problem's `master_zone` once, and every task it builds shares that copy (`_ZoneCopiedOnce`); a task built in a worker reads it once in that worker. Every other attribute, such as `_validated_data`, which the solver arrays use for input order and supplied flow rates, comes from the problem itself. Readers must not change the shared zone; the pinch design decomposition copies it before changing it [executor.py:_ZoneCopiedOnce, LocalSynthesisExecutor.execute, _build_and_solve_root_task] [../solver/pinch_design_decomposition.py:_zone_with_hen_dt_contribution].
- Settings are a frozen dataclass; only `evm_solver_options` is copied on construction, while `pdm_solver_options` and `tdm_solver_options` are shared references [settings.py:SynthesisWorkflowSettings.__post_init__].
- An option the width or depth sets keeps its explicit value when the configuration sets it (`None` means unset): `HENS_DT_CONT_MULTIPLIERS` for the width; `HENS_HEURISTIC_PDM_NETWORKS`, `HENS_HEURISTIC_PDM_EVOLUTION_SEEDS`, `HENS_PDM_MILP`, `HENS_EVM_N_AD_BRANCHES` and `HENS_EVM_N_RM_BRANCHES` for the depth. The minimum-unit network counts are not set by the depth. The executor resolves evolution breadth the same way [search.py:resolve_search] [executor.py:_evolution_options].
- The Couenne fallback applies only when the stage's configured solver is `couenne` (for pinch design, also `highs`, which hands a nonlinear model to Couenne), the stage has tasks and outcomes, and every outcome failed with a "couenne ... not found on PATH" error [fallbacks.py:_missing_couenne_failure]. A stage left at a default Couenne that is not installed already runs on SCIP (`configured_stage_solver`), so with default solvers the fallback is reached only when neither Couenne nor SCIP is installed; a stage explicitly configured with Couenne keeps it, so the fallback fires whenever Couenne is missing, SCIP or not [settings.py:configured_stage_solver].
- Utility-only networks (no active staged recovery exchanger) are not valid seeds [task_builders.py:has_recovery_topology].
- The fake executor requires successful parents for downstream tasks [fake_executor.py:FakeSynthesisExecutor.execute].

## Side Effects
- Spawns solver worker processes through `ProcessPoolExecutor` (one pool for each `execute` call, or one for a whole `session()`), falling back to serial when the pool raises `NotImplementedError`. The default pool raises it, after logging a warning, when the start method is not fork and the `__main__` script has no main guard, so it reads and parses that script, or `__main__` has no spec name and its `__file__` names no file (a script read from stdin or a string) [executor.py:_process_pool, LocalSynthesisExecutor._start_pool] [../../../optimisation/execution.py:_main_module_blocks_workers].
- Emits progress events [executor.py:LocalSynthesisExecutor._report_progress].
- With a pool and a record installed, starts a `multiprocessing.Manager` server process (unless `handoff_queue_factory` is given) and a drain thread for the stage's duration; with no record installed it starts neither [executor.py:LocalSynthesisExecutor._run, LocalSynthesisExecutor._handoff].
- Mutates its own bookkeeping (`executed_tasks`, `stage_order`, `problems_by_task_id`, `best_objective`) [executor.py:LocalSynthesisExecutor].
- Emits a `RuntimeWarning` when the Couenne fallback is taken [fallbacks.py:_warn_couenne_fallback].
- Emits a `RuntimeWarning` each time a missing default stage solver resolves to SCIP [settings.py:configured_stage_solver].
- Imports stage-packed model classes lazily [executor.py:_stage_packed_pdm_factory, _stage_packed_stagewise_factory].
